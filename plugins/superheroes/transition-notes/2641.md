### Before you upgrade

- **After switching.** **On a record this version writes, a caller that shows why a decision a finding cites is not on record reads the finding's new optional `decisionNotOnRecord` key, and reads any such warning in `reason` as history; on a record an earlier version wrote, the warning is in `reason`. A record does not say which version wrote it, so when you cannot tell, report the failure when the key is present and show `reason` as plain text.** The writer no longer adds that warning to the finding's `reason`. See [Review record: the not-on-record warning moves to its own field](#review-record-the-not-on-record-warning-moves-to-its-own-field).

### Review record: the not-on-record warning moves to its own field

- **The change.** When the record writer finds that a decision a finding cites is not on record, the finding stays or becomes `left-for-owner`, keeps its reason as it was, and carries the failure in a new optional key, `findings[].decisionNotOnRecord`, a non-blank string. Before, the warning that the cited decision, ruling or bound is not on record was added to the finding's reason, and a ruling that later resolved kept those stale words. The writer now adds no such words, and drops the key from any finding whose outcome is no longer `left-for-owner`.
- **One rule for reading it.** On a record this version writes, `decisionNotOnRecord` is the only current not-on-record failure, whatever the finding's outcome: a finding without the key has none as of that write. Warning words in its `reason` are history, carried from an earlier record (see Earlier records). On a record an earlier version wrote there is no key, and reading a stored record adds none, so the warning is in `reason`. A record does not say which version wrote it: every record reads `review-record/1`, and a lane still running an earlier version can write one after you switch. When you cannot tell which version wrote a record, report a not-on-record failure when the key is present, show `reason` as plain text rather than as a warning or as clear, and treat a finding without the key as not known to be clear.
- **Who reads it.** The PR sheet shows the key's text after the reason only for a finding listed for the merge verdict; an owner card shows only the context its author writes, so read `decisionNotOnRecord` when you write that card. The account validator refuses the key when it is not a non-blank string.
- **Earlier records.** A finding stamped by an earlier version keeps its words in `reason`, including when a later session carries it into a new record, whatever its outcome there (a resolved `ruling`, `fixed`, or still `left-for-owner`); nothing rewrites them.
- Nothing is removed or renamed.
