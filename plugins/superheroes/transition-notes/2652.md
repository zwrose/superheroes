### Before you upgrade

- **After switching.** **A caller of `check-build-ready --issue --repo` or `check-blockers` decides launchability from `ok`/`reason` and `held`, never from a non-empty `open`, which can now hold accepted lower layers; `--premise` is new and optional.** See [Issue contract: an accepted lower stack layer no longer blocks](#issue-contract-an-accepted-lower-stack-layer-no-longer-blocks).

### Issue contract: an accepted lower stack layer no longer blocks

- **The change.** An issue whose only open native blockers are lower layers of the same stack is launchable at once as a stack layer, when each such blocker is a handed-back pull request whose vet reads READY at its current head, or is held only for an owner card that rides the same stack's merge sheet. Any other open blocker still holds the issue. `check-build-ready --issue --repo`, `check-blockers` and the launch's base-state check all reach one helper that decides it. `check-blockers` takes an optional `--premise <file>`, the launch's own premise file. The rule is stated in `skills/showrunner/reference/routing.md` § Native dependency edges.
- **New keys.** `blockers` always carries `accepted`, `held`, `requiredDependency` and `stack`. `open` still lists every open edge, so it can name a blocker that no longer holds.
- A blocker's pull request is found from the links GitHub records (its closing references, or a stack layer's cross-reference on the blocker's timeline), not from the pull request's body.
- Nothing is removed or renamed.
