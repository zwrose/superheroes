### Before you upgrade

- **After switching.** **Nothing is owed: a storage-mode flip also moves the review decisions file and sets superseded legacy profiles aside, and `mode_migrate.py preview` gains `setAside`, `leftInPlace` and `overwrites`.** A caller that reads only the existing keys reads them as before. See [Storage move: the decisions file and legacy profiles](#storage-move-the-decisions-file-and-legacy-profiles).

### Storage move: the decisions file and legacy profiles

- **The change.** A flip carries the decisions copy reviews read now to the target side's slot: `<repo>/.claude/review-decisions.json` in the repo, `<project store>/config/review-decisions.json` out of it. When the review calibration file read now stays where it is, the original is kept as well, so the decisions are found whichever side is read after the flip. No copy is ever carried over the one read now. When a review calibration is read but no decisions file is, the flip carries nothing. When there is no review calibration at all (no review layer and no legacy profile), the flip carries the first regular decisions file on the moving side, replacing any copy at its target. It sets aside a second decisions copy, and each legacy review or test-pilot profile whose hero's layer moves in the same flip while a populated `core.md` supplies its facts, into one dated folder, `leftover-backups/<UTC stamp>-storage-move/` under the out-of-repo project store, with a `retired.json` manifest written before any copy. Every moved or set-aside file is copied byte for byte.
- **Files other sessions write stay behind.** The decisions copy read now and the legacy test-pilot profiles are files a review or a test-pilot run in another session may write while the move runs. So the move copies them and never deletes the originals: each original stays where it was and is named in `undeleted`. `python3 -B <plugin root>/lib/leftover_settings.py list --cwd .` lists them as leftover settings copies until they are retired: `retire --cwd . --owner-authorized true --list-digest <the listing's digest>` moves exactly that list to a dated backup folder. The session-start notice and configure's fix step that offer this to you come with the second layer of this change. This narrows the "no leftovers" promise for those files only. Until a legacy test-pilot profile left in place is retired, test-pilot keeps reading it, and the blocks beside it. A write landing on one of them during the move is never lost: it is at the original, at the copy, or both. Each one is copied a last time just before the switch, and once the switch makes the copy the one read, the move never copies over it again.
- **What the preview reports.** `mode_migrate.py preview` gains `setAside` (`[{"from", "to"}]`), `leftInPlace` (`[{"path", "why"}]`, `why` one of `only-copy`, `not-a-regular-file`, `shared-path`, `retained` (a decisions copy the flip neither carries nor sets aside), `has-artifacts` (a legacy test-pilot profile with blocks or manifests beside it, which stays so they are still found) and `kept-with-sibling` (a legacy test-pilot profile that stays because another one does, so the flip never changes which one is read)) and `overwrites` (each target path of a moved file that already exists and that the flip replaces).
- **What `execute` can now answer.** `{"status": "blocked", "reason": "recover-first"}` when an earlier move was interrupted and its journal is still at the store: nothing is changed; run `mode_migrate.py recover` first, then the move again. `{"status": "blocked", "reason": "plan-changed: …"}` when the tree changed between the plan `execute` was handed and the moment it takes the lock, inside one `execute` run (nothing is changed; run the move again). A separate `preview` run is not bound to it: `mode_migrate.py execute` plans afresh, so a change made after the preview command is moved on the new plan. `{"status": "done-with-leftovers", "undeleted": [<path>, …]}` when the move finished but left a source in place: a file other sessions write (above), one that could not be deleted, or one whose bytes changed after its copy and still differ after a few fresh copies (a source whose bytes are not at its copy is never deleted). Any finished move, `recover`'s included, adds `overwritten` (`[{"path", "backup"}]`) when it replaced a file already at a target path; that file's prior bytes are kept in a dated `leftover-backups/<UTC stamp>/` folder, never dropped.
- **Undo.** `python3 -B <plugin root>/lib/leftover_settings.py restore --cwd . --backup <folder>` puts a set-aside folder back; it never overwrites a present path and is refused in a cloud session. It returns set-aside files only: a carried decisions file stays where the flip put it.
- **What did not change.** The calibration files, definition documents and work-item records move exactly as before, and `calibration`, `definitionDocs`, `workItemRecords` and `disclosure` keep their meaning (a carried decisions file is listed under `calibration`).
- Replacement. None: no key or argument is removed.
