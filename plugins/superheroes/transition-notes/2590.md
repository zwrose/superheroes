### Before you upgrade

- **After switching.** **Nothing is owed by a consuming project: in the superheroes source repository an upgrade note is its own file in `plugins/superheroes/transition-notes/`, assembled into TRANSITION.md at the release doc pass.** No command, argument, result key or shape a consumer reads changes, and adopt-version reads the installed release's TRANSITION.md as before. See [Upgrade notes: one file per change, assembled at release](#upgrade-notes-one-file-per-change-assembled-at-release).

### Upgrade notes: one file per change, assembled at release

- **Where a note goes.** A builder writing an upgrade note writes it as its own file in `transition-notes/`, named for the issue (`<issue>.md`, or `<issue>-<slug>.md`), never into TRANSITION.md. Two changes never touch the same file, so their notes do not conflict at merge.
- **The shape.** A `### Before you upgrade` list of the change's bullets, each opening with `**Before switching.**` or `**After switching.**`, then the change's own `###` section or sections, with no `#` or `##` heading.
- **When it is assembled.** At the release doc pass, `scripts/pinned-python -B plugins/superheroes/lib/transition_notes.py assemble --plugin-root plugins/superheroes --version <X.Y.Z>`, run from the repository root, moves every note file into that version's section and removes the files. A hand-written `## Unreleased` section left in the file becomes that version's section.
- **What CI checks.** On every pull request, each note file must have that shape. A pull request that adds a `###` note heading or a Before-you-upgrade bullet straight into TRANSITION.md fails, unless the sections are those of note files it removes. A `###` heading reaches TRANSITION.md only through a note file's assembly: to change a note's heading, edit its note file before the doc pass; a released section's heading cannot be renamed without CI failing. The release pull request fails while any note file is still unassembled.
- **Readers.** A test or tool that reads TRANSITION.md's unreleased wording reads `transition_notes.transition_text(<plugin root>)`, which renders the unassembled notes as `## Unreleased`. adopt-version is unchanged.
- Replacement. None for a consumer.
