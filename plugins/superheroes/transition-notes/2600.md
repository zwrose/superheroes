### Head coverage: a builder's code-conflict fix is judged by the vet

- **What a reader sees differently.** A builder's merge of the base into the PR that hand-fixed a code conflict answers `judgement` with why token `conflict-fix`; it answered `needs-review` with `behaviour-change`. Each hunk carries the keys `file`, `header`, `merge`, `parents`, `mergeBase`, `kind` (`conflict-fix`) and `text`: git's own automatic merge of the file, conflict blocks and their markers included, as `-` lines against the builder's merge as `+` lines. A code conflict fix now keeps the owner's merge word when the vet clears it with `--judged-clear` and the carry check, run from the sheet's commit with `--carry-judged-clear`, covers it. The check lists every line of the merge that git's automatic merge did not make, and may list a line git's real merge made, never fewer than the builder typed. The builder for the author test is `--builder-author` when given, else the author email of the commit the record certifies; the vet passes the same value on both checks.
- **What stays `needs-review`.** A non-merge commit; a merge whose second parent is not on the base; a merge whose first parent is neither the certified commit nor another such merge; a commit by anyone but the builder; a rename or copy; a mode change; a `merge` or `conflict-marker-size` attribute on the file; a NUL byte; more than one merge base; a hand edit in a file git merged without a conflict (a file neither parent changed included); a conflict block left with its markers; any git read that fails. A clean merge stays `proven`, and a head identical to a tested union probe stays `proven` (`proven-union`).
- **The sheet line.** The sheet input's `carriedForward` takes an optional `conflictFix`, a non-empty string, the vet's one-line reason. A sheet built with it shows one line on the page and in the chat prose: "A code conflict was fixed when the base was brought in, and it was judged immaterial: <conflictFix>". A carry without it still shows no note.
- **What the builder does on a conflict.** The builder makes the merge commit, pushes it and hands back; the vet judges the conflict fix first, and a scoped returning review of the merge runs only when the vet calls the fix material or the check answers `needs-review` for another reason. This replaces the step "runs the returning review on the merge" in the note "Merge train: a conflicting PR goes back to its builder".
- Replacement. None: no key, token, argument or result shape changes on any other answer.
