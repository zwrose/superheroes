### Before you upgrade

- **After switching.** **Nothing is owed: a project with leftover settings copies sees one short notice at the start of every session, and configure routes it to the fix path; retiring them is optional and asks first.** A project with none sees no change. See [Leftover settings copies: named at session start, retired by configure](#leftover-settings-copies-named-at-session-start-retired-by-configure).

### Leftover settings copies: named at session start, retired by configure

- **The change.** A leftover settings copy is an old copy of a settings file that sits beside the one the project's storage setting reads first: a core, pattern, guardian or hero layer file, a review or test-pilot legacy profile, or a review decisions file. Only a project with a recorded storage mode has any, and a file that is the only copy is never one.
- **What a project with leftovers sees.** The session-start context gains a short "Leftover settings copies" notice that names each copy (up to ten, then a count of the rest) and says how to retire them; an old test-pilot profile a storage move left in place is marked as the one test-pilot still reads until it is retired. `/superheroes:configure` shows the same wording under a `## Leftover settings copies` heading in its one-screen view, and its route sends the project to the fix path with the reason "old settings copies sit where the storage setting does not read". A project with none sees the same session start, view and route as before.
- **Retiring them.** The fix path's "Retire leftover settings copies" step lists the copies and moves them only after the owner says yes in that turn. It moves them into a dated folder, `leftover-backups/<UTC stamp>/`, under the out-of-repo project store, with a `retired.json` manifest written before any move. Nothing is deleted. To undo it, run `python3 -B <plugin root>/lib/leftover_settings.py restore --cwd . --backup <folder>`, which never overwrites a present path. The step is refused in a cloud session and runs on the owner's machine.
- Replacement. None: no key or argument is removed; configure_view's collect gains a key.
