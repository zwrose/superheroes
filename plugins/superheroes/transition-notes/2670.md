### Before you upgrade

- **After switching.** **A caller that feeds a conformance report to `pilot_acceptance.py matrix` runs `pilot_conformance.py run` with `--project <name>`, the same name it passes the matrix, in a checkout at the commit it passes the matrix.** The matrix now refuses a report that does not name that project and commit. See [Pilot acceptance matrix: the report must name its project and commit](#pilot-acceptance-matrix-the-report-must-name-its-project-and-commit).

### Pilot acceptance matrix: the report must name its project and commit

- **The change.** `pilot_conformance.py run` gains an optional `--project <name>`; with it the report carries a new top-level key, `reference: {project, commit}`, where `commit` is the full object id of `--cwd`'s HEAD. A run with `--project` reads its stamp, branch, calibration and exercises with every git routing variable (`GIT_DIR` among them) removed. When that commit cannot be read the run refuses `conformance-cli-commit-unreadable`, and an empty `--project` refuses `conformance-cli-project-invalid` (both exit 2). A new verb, `pilot_conformance.py head --cwd <path>`, prints the commit a bound run stamps.
- **Newly required.** `pilot_acceptance.py matrix`, and the library's `matrix()`, now require the report's `reference` to name the same `project` and `commit` as the matrix's reference. A report with no `reference`, or one naming only one of the two, refuses `acceptance-report-unbound`; a differing commit refuses `acceptance-report-commit-mismatch` and a differing project `acceptance-report-project-mismatch` (exit 2, the second stderr line naming each differing value). A report written before this change carries no `reference`, so it refuses as unbound.
- Replacement. Pass the matrix's `--project` value to the conformance run as `--project`, and take the matrix's `--commit` from `pilot_conformance.py head --cwd <the run's --cwd>`, as the plugin's own set-up and test-pilot-init steps now do. Nothing else in either output is removed or renamed.
