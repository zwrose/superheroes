## BP14 — byte enumeration + raw-byte hashing in digest producers (C2, C3)

**Guarded element:** `engine_dispatch.py:_worktree_porcelain_snapshot` and `_legacy_worktree_porcelain_sha256` — axis: **raw-byte porcelain hashing**.

**Neutralization:** restored `text=True` git calls and `porcelain.encode("utf-8")` hashing on both producers.

**Raw red** (nodes `test_probe_producers_distinguish_cr_from_lf_in_pathnames[snapshot_filtered]`, `[snapshot_plain]`, `[legacy]`):

```
...                                                                      [100%]
3 passed in 1.12s
```

**Unobservable axis (disclosed).** The CR/LF collision was never reachable on the non-`-z` digest producers (C2/C3): git C-quotes a pathname containing `\r` in non-`-z` porcelain (`no -z` → `b'?? "a\\rb"\n'` with no raw CR byte; `with -z` → `b'?? a\rb\x00'` with raw CR present), so the byte is quoted before it is ever decoded. This axis is not observable there and no neutralization of it can redden. The byte move on C2/C3 is defensive uniformity, not a demonstrated-defect fix — it removes a locale-dependent decode and makes the invariant hold at every producer. What actually pins C2/C3 is the digest-compatibility test (`test_probe_digest_compatibility_ordinary_tree`), which proves the change alters no digest on an ordinary tree.

**Restore:** inverse edit — restored `_git_scrubbed_bytes` and `hashlib.sha256(porcelain)` on both producers.

**Restore receipt:** restored byte reader + raw-byte hash on C2/C3.
