## BP1 — digit bound (interpreter-independent)

**Guarded element:** `_bounded_stdout_marker_claimed_bytes` length bound — axis: just-over-bound forged digit run yields `markerBytes: null` without raising on the suppression path, on every supported interpreter.

**Neutralization:** removed the `len(digits) > _STDOUT_MARKER_CLAIMED_BYTES_DIGITS_MAX` guard so a `MAX+8`-digit marker reaches `int()`.

**Interpreter independence:** local `/usr/bin/python3` is 3.9.6 (no `sys.set_int_max_str_digits`). The new case uses `MAX+8` digits (40), far below CPython 3.11+'s default 4,300-digit `int()` conversion limit, so `int()` succeeds on 3.9 and 3.12 alike; with the bound removed the extracted value is a real integer and `markerBytes is None` fails everywhere. The retained 5,000-digit case covers the `ValueError` defence path on 3.11+ but its bite-proof red is interpreter-dependent (passes on CI when only `int()` raises).
