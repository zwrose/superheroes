## BP-FIX5-1 — the full-envelope presence check

**Guarded element:** `plugins/superheroes/lib/round_records.py:531` —
`env_exists = os.path.lexists(env_path)` inside `_read_landing_envelope`.

**Detector:**
`plugins/superheroes/lib/tests/test_round_driver_advance.py::test_record_result_sweep_recovery_reports_dangling_envelope_symlink`.

**Axis it claims — truthfulness of the refusal about a landing that IS present.** The refusal
(`sweep-supersede-unsupported`) fires either way; what this line guarantees is that presence is
decided from the DIRECTORY ENTRY. A landing slot occupied by a dangling symlink at `landing_path`
is present, so the slot must produce a recovery entry naming the refusal reason (`landing-torn`)
and the stored CAS token — and therefore the no-recovery `detail` string ("no slot has both a
stored record and a pending landing that differs from the stored envelope") must not be emitted.
The `"no slot has both" not in out["detail"]` assertion is the line that carries this axis.

**Why the neutralization reaches the detector.** `os.path.exists` follows symlinks, so the dangling
entry reads absent, `_read_landing_envelope` returns `landing-missing`, and
`round_driver._cmd_record_result_locked`'s recovery loop takes its one silent `continue` — the
carve-out reserved for "there is genuinely nothing landed" — leaving `recovery == []` and re-emitting
the false detail.

**Neutralization** (targeted, reversible edit applied to the source, the test unedited; line 532
left as `lexists`; reverted by the inverse edit — no `git checkout`, `git restore`, `git reset` or
`git stash` was used at any point):

```diff
-    env_exists = os.path.lexists(env_path)
+    env_exists = os.path.exists(env_path)
```
