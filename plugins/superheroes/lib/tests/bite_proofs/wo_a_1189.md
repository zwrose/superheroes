# WO-A (#1189) bite-proof — entry-presence semantics at the four remaining `round_records` presence checks

**Declared guarded-element set — five, and these five exactly.** Declared in the build brief before
code, unchanged since.

1. `sweep_landing`'s `has_landing` entry presence (site 1) → `test_sweep_reports_dangling_roster_landing_symlink_as_landing_torn`
2. `validate_landing`'s store-entry presence (site 2) → `test_ingest_refuses_dangling_symlink_store_entry`
3. `sweep_landing`'s `already-stored` entry-vs-target split (site 3) → `test_sweep_refuses_dangling_symlink_store_entry_not_already_stored`

5. the census assertion itself → `test_round_records_presence_checks_use_entry_not_target`

Every proof below was produced **twice**: once by the implementer (cursor / composer-2.5, its
verbatim runs are in the WO-A run journal) and once **re-run by the orchestrator** on the final head
`fa953185`, which is what this record carries. Every mutation was applied and reverted with a
**targeted edit**, never a whole-file rewrite and never `git checkout --`; the landed work was
committed first, so no revert could reach uncommitted work. `git status --porcelain` was **empty**
after the last restore — the tree is byte-identical to the commit.

Selection is by **exact node id**, never a loose `-k` substring. All runs carry
`-B -X pycache_prefix=/private/tmp/superheroes-pyc` — every mutation here is a same-second,
near-same-size edit, exactly the shape that otherwise runs stale bytecode and makes a proof a lie.

Outputs below are the **captured tail** of each run — labelled as such, not reconstructed. The

## BP-5 — the census assertion itself

- **guarded element:** `test_round_records_presence_checks_use_entry_not_target`
- **axis:** `round_records.py` contains **no `os.path.isfile(`** and **no `os.path.exists(`** — the
  two spellings that answer about the symlink target

The test pins both spellings as **string literals in the test body**, not as symbols or f-strings: a
symbol-spelled constant would be green under any value, which is the vacuity this axis exists to
avoid.

**neutralization:** reintroduce one `os.path.exists(` call anywhere in the module. BP-1's
neutralization does exactly that, so BP-1's red run above **is** this element's red run — recorded
there rather than duplicated here, and its green is the same `2 passed` line.

**Why this element is declared at all:** BP-1..BP-4 each prove one site behaves correctly today.
BP-5 is what makes a **fifth** site added later — or a regression at any of the four — fail a test
rather than ship. It is the invariant assertion; the other four are the per-site end states.

---

## Limits of these proofs — stated, not implied

- Each proof shows its named test **red** under a mutation of its own element and **green** on the
  final head. It does **not** show the test is red under every possible wrong implementation.
- BP-5's axis is a **source-text** assertion. It catches the two forbidden spellings by name; it
  would not catch a semantically equivalent target-following check written some other way (say a
  bare `os.stat` outside a try, or an `os.path.isdir`). That limit is real and is why BP-1..BP-4
  test **behaviour** rather than leaning on BP-5.
- No proof here runs under a normalization: the assertions compare literal strings and refusal
  reasons directly.
