## How these proofs were produced — the claim, stated exactly

**Every proof below was re-run by the orchestrator on the FINAL head** — the head this record ships
on, after round-2's fix commit. Captures made against intermediate heads were **discarded and
replaced, not carried forward**. That is not a formality: a prior revision of this file cited line
numbers that had gone stale by twelve when a test was inserted above them, and separately claimed a
head SHA that was not a commit on this branch. The review caught both. Every line number and every
outcome below comes from a run made after the last code change.

Mechanics, all load-bearing:

- Each mutation was applied and reverted with a **targeted edit**, never a whole-file rewrite and
  never `git checkout --`. The landed work was **committed before any probe**, so no revert could
  reach uncommitted work.
- Selection is by **exact node id**, never a loose `-k` substring.
- Every run carries `-B -X pycache_prefix=/private/tmp/superheroes-pyc`. These mutations are
  same-second, near-same-size edits — precisely the shape that otherwise runs **stale bytecode** and
  turns a proof into a lie. Runs also pin `PYTEST_DEBUG_TEMPROOT` to a scratch root; that is a local
  `source_guard` workaround and has no bearing on what is proven.
- After the last restore, `git status --porcelain` printed **nothing** — the tree is byte-identical
  to the commit — and the two exercising files ran **165 passed**.

Most probes were run **paired**: the mutated element's test alongside a sibling element's test, so
one capture shows the target **red** and the sibling **green**. That pairing is the
**separate-neutralizability** evidence the DoD asks for.

Outputs are the **captured tail** of each run, labelled as such and never reconstructed. Paths are
elided to `…` where the full path adds nothing; the file is always
`plugins/superheroes/lib/tests/test_round_records.py`.

## BP-6 — element 6: the census assertion, both legs

- **axis:** `round_records.py` contains **no `os.path.isfile(`** and **no `os.path.exists(`** — the
  two spellings that answer about the symlink target rather than the entry

Both spellings are pinned as **string literals in the test body** (`:856`, `:857`), not as symbols
or f-strings: a symbol-spelled constant would be green under any value, which is the vacuity this
axis exists to avoid.

**This element has two legs and each is proven separately** — round-2 review found an earlier
revision in which only one leg had ever been reddened:

- **`exists` leg (`:857`)** — reddened by BP-1's mutation; the capture is in BP-1 above.
- **`isfile` leg (`:856`)** — reddened by BP-5's mutation; the capture is in BP-5 above.

Recorded by **cross-reference rather than duplicated runs**: each leg's red is a real capture above
with its own distinct line number, and re-running the identical mutation would add no evidence.
Nothing here is inferred.

**Why this element is declared at all:** BP-1..BP-5 each prove one site behaves correctly today.
BP-6 is what makes a *new* target-following presence check — at a site nobody enumerated — fail a
test rather than ship.

## Controls — green on both revisions, and NOT guarded elements

These six tests are deliberately **not** in the declared set. Each pins behaviour the change must
**not** alter, so each is green before and after. They are listed because a reader counting tests
against guarded elements would otherwise find six unexplained — and an unexplained green test is
indistinguishable from an unproven detector.

- **T3b** `test_sweep_skips_real_directory_named_like_landing_file` — a stray filter that reported a
  real directory named like a landing file as a stray would fail this.
- **T4** `test_sweep_already_stored_when_store_file_is_unparseable_not_a_symlink` — a split that
  discriminated on JSON-readability rather than entry-vs-target would fail this. It is what makes
  "readability is not the discriminator" enforceable rather than aspirational.
- **T5** `test_sweep_refuses_out_of_session_dangling_landing_symlink_at_path_build` and
  **T5b** `test_sweep_refuses_out_of_session_dangling_bare_payload_symlink_at_path_build` — a sweep
  that swallowed an out-of-session dangling landing (either arm) instead of refusing `bad-argument`
  would fail these. T5b was added in round 2, after an audit found the round-1 fix had re-silenced
  the bare arm.
- **T6** `test_ingest_refuses_out_of_session_dangling_store_symlink_at_path_build` — a path builder
  that swallowed an out-of-session dangling store entry instead of refusing `invalid-path` would
  fail this.
- `test_guard_within_refuses_symlink_escape` predates this change, is untouched, and guards a
  different fence.

## Limits of these proofs — stated, not implied

- Each proof shows its test **red** under a mutation of its own element and **green** on the final
  head. It does **not** show the test is red under every possible wrong implementation.
- **Element 6's axis is a source-text assertion.** It catches two forbidden spellings by name; it
  would not catch a semantically equivalent target-following check written another way — a bare
  `os.stat` outside a `try`, or an `os.path.isdir`. That limit is exactly why elements 1–5 and 7
  test **behaviour** rather than leaning on element 6.
- **Element 6's legs are recorded by cross-reference**, not by two dedicated runs (BP-6 states why).
- **Scope limit on elements 1–4** — a stated limit, not a proof gap: `landing_path` / `store_path`
  route through `_guard_within`, which decides containment on `realpath`. A dangling symlink whose
  dead target lies **outside** the session refuses at path-build time (`bad-argument` /
  `invalid-path`) before any `lexists` runs. Those are enumerated loud refusals, so the silent-skip
  class is closed either way; controls T5/T5b/T6 pin that boundary. **Element 5 carries no such
  limit** — the stray scan `lstat`s a bare `os.listdir` join with no fence on the leaf.
- No proof here runs under a normalization: assertions compare literal strings and refusal reasons
  directly.
