## E7 — layer 2, the per-test residue detector

**Guarded element:** the `pytest.fail` in `_check_residue` — axis: a mutation the audit hook cannot see must still fail the test that caused it, **by name**.

This element has no in-memory unit test, because layer 1 would block an in-process write
before layer 2 could observe it. The probe therefore drives the case layer 2 uniquely owns:
a **subprocess** write to a watched shipped file, left unrestored. The probe file lived in
the test tree only for the duration of these two runs and was moved out afterwards.

**Neutralization:** `if changed:` → `if False and changed:` in `_check_residue`.

**Red run** (mutation goes uncaught by layer 2 — the test *passes*):
```
.                                                       [100%]
1 passed in 0.05s
```

**What the red run also showed — layer 3 still fired:**
```
source_guard: session left shipped source dirty: .../plugins/superheroes/lib/handback_gate.py
```
The session-end `git status --porcelain` ground truth caught what the neutralized layer 2 missed.
That is the layered design working, recorded here rather than claimed.

**Restore:** inverse edit restoring `if changed:`.

**Green run** (fails by node id, naming the mutated file):
```
E           Failed: source_guard: shipped source mutated by
            plugins/superheroes/lib/tests/test_zz_residue_probe.py::test_subprocess_mutates_shipped_source_unrestored:
            .../plugins/superheroes/lib/handback_gate.py
```

After both runs `plugins/superheroes/lib/handback_gate.py` was restored from a pristine
pre-run copy; SHA-256 `73a49a52a335ef8acbb7fc990faab8c081b35787ec1618845771d37ca2cb3f54`,
identical to `origin/main`'s.

## Residuals (stated, not claimed away)

- A same-size rewrite whose `mtime_ns` is restored with `os.utime` is not attributed to its
  individual **test** by layer 2's `lstat` shortcut; layer 3 still catches it at session end,
  without a test name.
- No layer promises anything about a `SIGKILL` landing mid-write.
- Under xdist, a worker mutating shipped source can fail a **sibling** worker's test, so
  first-failure attribution is exact only in serial runs.

## Orchestrator self-check on D4a/D4b — a measured residual

The two new load proofs (`test_guard_loads_without_explicit_plugin_flag`,
`test_guard_loads_from_nested_test_directory`) build a **synthetic** repo in `tmp_path` that
carries its own `pytest.ini` and its own `conftest.py`. They therefore prove the *mechanism*
— that a root `conftest.py` plus a rootdir-pinning `pytest.ini` makes the guard load, including
from a nested `cwd` — but they do **not** depend on **this** repository's `conftest.py` or
`pytest.ini`.

Measured by the orchestrator, not predicted:

```
# real repo pytest.ini moved aside
$ pytest .../test_source_guard.py::test_guard_loads_from_nested_test_directory -q
1 passed in 0.93s          # expected red; the test does not observe the real repo

# real repo conftest.py's pytest_plugins line removed
$ pytest .../test_source_guard.py::test_guard_loads_without_explicit_plugin_flag -q
1 passed in 1.37s          # expected red; same reason
```

**Consequence, stated rather than claimed away:** deleting this repo's root `conftest.py` or
`pytest.ini` would silently un-wire the guard for real runs, and no test would go red. The
panel finding that asked for this (test-reviewer, "Wiring tests cannot detect that the global
guard stopped loading") is **mitigated but not closed**.

The guard's *behaviour* in the real repo was verified directly instead, from the previously
broken invocation shape:

```
$ cd plugins/superheroes/lib/tests
$ pytest <probe> -q -s
ROOTDIR:  <repo root>
RESOLVED: <repo root>   WATCHED: 170
handback_gate WATCHED (want True): True
test_handback_gate WATCHED (want False): False
source_guard.py WATCHED (want True): True
```

Before `pytest.ini`, that same shape gave `rootdir: .../plugins/superheroes/lib/tests` and
`ModuleNotFoundError: No module named 'source_guard'` — the guard was absent entirely.

**Why this was not fixed in-build:** the third-rework tripwire fired on this surface. The
seam problem is named in the PR body, and closing it is a disclosed follow-up — the fix is a
*structural* pin (assert the real `conftest.py` and `pytest.ini` carry the wiring), not another
behavioural subprocess proof, because a test that builds its own repo can never witness a
property of this one.
