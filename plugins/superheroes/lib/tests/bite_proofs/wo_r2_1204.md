## BP-R2 — uncovered-rounds arm

- **axis:** **cross-round** disclosure — a surviving per-round line on round 2 must not drop round 1's
  unjudgeable receipt from degraded prose.

**Scope correction (orchestrator, round 3).** The axis above is **cross-round, not whole-history**,
and an earlier wording of this record over-claimed by calling it "whole-history". A round-3 review
seat and its verifier established the gap, and the seat's own read-only reproduction is the
evidence: coverage is subtracted by **round key alone**, so a *same-round*
`no-seats` → `no-author-family` re-fold discloses only the later basis —
`state["rounds"]["1"]["seatMapUnjudgeable"] == ['no-author-family']` and the receipt carries only
`seat-map-unjudgeable (round 1): … (no-author-family)`, with the earlier `no-seats` absent. **This
guard does not cover that case, and this record no longer claims it does.**

**Why it is not fixed here — the third-rework tripwire fired.** Fixing it would be the **third**
corrective pass on `unjudgeable_run_level_disclosure` in one build (WO-R1, the round-2 fix, and
this), and `rubric/review-discipline.md` § *The third-rework tripwire* forbids the fourth patch on a
surface. **The seam, named:** run-level coverage is keyed by **round**, but a round's per-round
record is **last-write-wins on basis** while the receipt history is **append-only** — so the two
disagree whenever one round submits maps with two different incomplete bases. The proper repair
keys coverage by `(round, basis)`, which changes what the per-round record *means*, not just this
function's arithmetic. Shipped as a **disclosed follow-up**.

**Fail direction, stated rather than implied:** the run still certifies `-degraded`, still emits a
named `seat-map-unjudgeable` line, and still names the round and one real basis. What is lost is a
**second basis inside an already-disclosed round** — incomplete enumeration within a disclosure that
fires, never a silent clean certification. A round-1 verifier separately established that a
same-round second `_fold_panel` is not reachable through normal driver entrypoints (after the first
panel `state["step"]` is `P_VERIFIERS`, and an exact replay returns `duplicate` before folding), so
the case is exercised by tests rather than by production runs.
