# Bite-proof record — #1223 (five pilot budget-race tests + one census sibling; the probe helper's zombie reading)

**What changed:** six completion-path pilot tests stopped racing a short wall-clock budget, and
`grandchild_probe._observed_process_state` now reads a zombie as gone when `/proc` is absent (it
used to trust `kill(pid, 0)`, which succeeds for a zombie). Both are detector changes, so this
record carries a red→green proof for each guarded element, taken at the build's final head
`54b01367` in a detached probe worktree. Every mutation was a targeted edit through the host's edit
action, reverted by the inverse edit. After the last revert, `git status --porcelain` in the probe
tree was empty and the guarded set was green again (`12 passed`).

## Diagnosis (why the tests raced, measured before any change, on `5de88598`)

- **Fresh-exec assessment queue (tests 1–3, 5, 6).** Each test writes a new `#!/bin/sh` script and
  runs it. macOS assesses a freshly written executable (it carries `com.apple.provenance`) on its
  first exec, and those assessments queue system-wide. A two-line script took 0.17 s p50 when run
  serially. With 36 concurrent first execs it took **p50 3.36 s, p90 5.62 s, max 6.05 s**. Reusing an
  already-executed script took ≤ 0.034 s under the same concurrency, and 72 CPU spinners with a
  reused script stayed ≤ 0.03 s. So CPU load alone does not reproduce it. `Popen` returned in
  ≤ 34 ms every time, so the cost lands inside the budget `reader.join(timeout)` spends. Serial runs
  pass because one fresh exec costs about 0.17 s against 5 s.
- **Child CPU cost (test 4, the drain test).** Its child made 307,200 one-byte builtin `printf`
  writes: 7.8 s real / 2.4 s CPU standalone, and 6.3 s through the runner at load average 38. That
  time scales with load, against a 30 s budget.
