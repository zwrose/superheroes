# Reset C16 (#1275) bite-proofs — the detectors this branch owed

The branch retires far more detection than it adds. Three elements are **born** here and owe a
proof; nothing else on this branch is a new detector.

Every proof below was **produced and re-run by the orchestrator**, not inherited from an implementer
report. Each mutation was applied as a targeted revertible edit through the host's edit action —
never a whole-file rewrite, never an ad-hoc shell edit, never a git discard — and each was reverted
by its **inverse edit**.

**Where the probes ran.** In a **detached worktree of its own** (`/private/tmp/c16-probe`) pinned to
commit `8b4bc9f9`, never in the build worktree, so no concurrent read-only seat could grade a tree
mid-probe. The worktree was removed afterwards with `git worktree remove`.

**Normalization, stated because it changes what the runs mean.** Every command ran under
`-B -X pycache_prefix=/private/tmp/superheroes-pyc-probe` so Apple Python's out-of-tree bytecode
cache could not serve stale objects across same-second edits — the exact shape of every mutation
here. Each red and green run selected its test by **exact node id**, never by `-k`.

**Tree state after the probe sequence:** `git status --porcelain` empty, `git diff HEAD --stat`
empty, and `grep -c 'if False' plugins/superheroes/lib/sanitized_view.py` = **0**.

## BP-C16-4 — the review patch fails closed on what it cannot account for

**Guarded element:** the two refusals in `_filter_patch_sections` — a non-`diff --git` span, and a
section whose path will not decode. Before the fix both were silently dropped, which is how a
changed file could vanish from a review with nothing to show for it.

**Neutralization:** both together, since either alone still catches part of the surface — the
unrecognized-span condition replaced by a constant-false condition, and the undecodable-path branch
turned back into a `continue` with the raise left in place, unreachable.

## BP-C16-5 — C-quoted paths are decoded, not dropped

**Guarded element:** the C-quote decode branch in `_path_from_minus_plus_rest`. `core.quotePath=false`
governs only bytes above 0x7f; git still C-quotes a name containing a quote, a backslash, or a
control character, so without this branch such a file has no resolvable path.

**Why the literal and not the symbol:** the branch is selected by a byte-string literal, and a test
that exercises decoding is green under any value the guard happens to carry. The probe moved the
literal — `b'"'` to a byte sequence git never emits — rather than deleting the branch.

**Red run:**

```
>               raise SanitizedViewError("sanitized-view-diff-unaccounted")
E               sanitized_view.SanitizedViewError: sanitized-view-diff-unaccounted
FAILED test_review_diff_quoted_path_is_decoded_and_kept
1 failed, 1 passed in 0.62s
```

**What the second, still-passing test proves, and why it is recorded rather than tidied away.**
`test_review_diff_quoted_stripped_path_is_withheld` stayed green under the neutralization — because
with decoding gone the section refuses instead, and a refused view also never leaks the stripped
content. That is the layering working: decoding is the *correctness* guarantee, the fail-closed
refusal is the *containment* backstop, and neutralizing the first does not silently defeat the
second. A single test covering both would have hidden it.

**Green run** after the inverse edit, both node ids: `2 passed in 0.59s`.
