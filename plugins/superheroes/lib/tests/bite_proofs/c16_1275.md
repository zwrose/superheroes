# Reset C16 (#1275) bite-proofs — the detectors this branch owed

The branch retires far more detection than it adds. Three elements are **born** here and owe a
proof; nothing else on this branch is a new detector.

Every proof below was **produced and re-run by the orchestrator**, not inherited from an implementer
report. Each mutation was applied as a targeted revertible edit through the host's edit action —
never a whole-file rewrite, never an ad-hoc shell edit, never a git discard — and each was reverted
by its **inverse edit**.

**Where the probes ran.** In a **detached worktree of its own** (`/private/tmp/c16-probe`) pinned to
commit `8b4bc9f9`, never in the build worktree, so no concurrent read-only seat could grade a tree
mid-probe. The worktree was removed afterwards with `git worktree remove`.

**Normalization, stated because it changes what the runs mean.** Every command ran under
`-B -X pycache_prefix=/private/tmp/superheroes-pyc-probe` so Apple Python's out-of-tree bytecode
cache could not serve stale objects across same-second edits — the exact shape of every mutation
here. Each red and green run selected its test by **exact node id**, never by `-k`.

**Tree state after the probe sequence:** `git status --porcelain` empty, `git diff HEAD --stat`
empty, and `grep -c 'if False' plugins/superheroes/lib/sanitized_view.py` = **0**.

## BP-C16-1 — the review-only file's size cap

**Guarded element:** the `CONFIG_CHANGES_MAX_BYTES` ceiling in `_stage_config_changes`, which
refuses `sanitized-view-diff-config-too-large` rather than writing an unbounded configuration diff
into the view.

**Neutralization:** the size comparison replaced by a constant-false condition, leaving the raise
in place and unreachable (`if len(body_bytes) > CONFIG_CHANGES_MAX_BYTES:` → `if False:`). The raise
itself was left untouched on purpose: a proof that deletes the raise proves only that a deleted
raise does not fire.

## BP-C16-2 — the review-only file's collision refusal

**Guarded element:** the two-part collision refusal in `_stage_config_changes` — the
`os.path.lexists` pre-check and the `O_EXCL` flag on the open — which together refuse
`sanitized-view-diff-config-path-collision` rather than writing through something already sitting at
the file's name in the view.

**Neutralization:** both halves, because either one alone still refuses and a proof that neutralizes
only one measures the other. The `lexists` condition was replaced by a constant-false condition
(raise left in place, unreachable) **and** `os.O_EXCL` was dropped from the open flags.

## BP-C16-3 — the review-only file is not discoverable as configuration

**Guarded element:** the value of `CONFIG_CHANGES_FILE_NAME`. The whole design rests on a seat being
able to read the file as data without any tool loading it as its own configuration, and what
guarantees that is the name itself — outside both discovery lists, outside every configuration
directory, and carrying an extension no discovery rule reaches.

**Why the literal and not the symbol:** a test that asserts "the constant is not in the list" is
green under *any* value the constant happens to hold, so the probe has to move the literal. It was
set to `"CLAUDE.md"` — the exact spelling a careless name would have collided with.
