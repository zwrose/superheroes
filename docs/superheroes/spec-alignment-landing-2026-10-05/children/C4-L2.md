What: Discovery draws before it writes, replacing today's step 4 ("UI/UX when relevant") in `plugins/superheroes/skills/architect-discovery/SKILL.md` and adding whatever reference the drawing steps need. Discovery draws journeys or flows first, then open choices side by side, then a build board holding only the settled design, with everything that can reasonably be drawn drawn and the real wording in place; any visual that communicates counts (screens, storyboards, flow charts, diagrams). Every board is an HTML artifact carrying the project's design system for the product it draws, with its own frame and labels in the Comic panel theme loaded from the one stylesheet (R19), and is never less detailed than the chat it draws from; where the host can't show an HTML artifact (a Codex host), the board is the local HTML file the project keeps, opened in a browser. When the owner approves the build board it is saved as a file the project controls, kept with its spec. Where a project has turned on syncing to Claude Design the approved board syncs to it once, at approval; where a project uses Claude Design, its boards' design system comes from there whether or not syncing is on. A small piece with nothing to draw may skip the board, and its spec is then written from the framing and rulings. Where the spec and the approved board disagree, the board wins and the spec is corrected; a ruling that changes something an approved board shows is redrawn, and the redrawn part is marked to go on the owner's next sheet (layer 4 sends it).
