What: Break-it tests are written by the test reviewer and run by the build session, in its own working copy, before the verifier grades. Today the test role (`plugins/superheroes/agents/test-role.md`) writes at most three break-it tests per review on touched risk areas, and the loop runs them with `plugins/superheroes/lib/break_it.py` in a throwaway detached copy of the reviewed head, a failing run becoming a finding. This layer:
- has the test reviewer attach a break-it test to each finding it can prove that way, and keep writing per-area tests on touched risk areas: at most three per review, at least one per touched area while under that cap, the cap counting only these per-area tests, each delivered as a finding; tests attached to findings and second tests have no cap (FR-11); the build session never writes one;
- keeps the test reviewer's checks for tests that pass by chance, flaky tests and fixes with no test that would fail, counting test bloat against the change, asking no coverage in low-risk code and flagging no style preference (FR-12);
- adds the step where the build session runs each attached break-it test on the unfixed code, exactly as written, in its own working copy, and saves the output without judging it, so the output is in the verifier's hands when it grades (FR-13; the verifier is C1-L7's);
- removes every throwaway copy from code review's test runs: `break_it.py`'s detached copy, its linking of dependency directories, and the test role's rule that the loop runs its tests in one (FR-50);
- lets the build session make the small change a break-it test needs to run, such as a compile or type error, recording why, so the review goes on to the verifier and never ends unable to certify over it (UFR-4).

DoD:
- Tests on the test reviewer's contract: a finding it can prove carries an attached break-it test; per-area tests stop at three per review and reach every touched area while under three; attached tests are not counted against the three; each per-area test arrives as a finding (FR-11, both acceptances). The agent's text says it asks for no low-risk coverage and flags no style preference, and keeps its chance-pass, flaky and no-failing-test checks (FR-12).
- Driver tests: before the verifier phase, each attached break-it test has been run once on the unfixed head in the session's working copy, exactly as written, and its output is saved with the finding; nothing grades it at that step (FR-13).
