Journey 1 · once per project, per Claude account

Setting a project up for the cloud

You ask the advisor to set the project up for cloud builds

↓

The advisor writes the setup text for you to pasteIt carries the plugin at the advisor's version, the tools a build needs, and the project's calibration when that is kept outside the repo.

↓

It tells you two things plainlyWhere the reviewer pass will sit and who can read it. And that cloud builders do not get your personal rules, only the project's and the plugin's.

↓

You make the cloud environment and paste, by handThe setup text and the reviewer pass. Hands-off upkeep is the later piece.

↓

A short check session proves itSame plugin version as the advisor, calibration matches, the reviewer answers.

↓

It passes: you can switch cloud builds onA per-project setting. Off until now.
It fails: the switch stays offThe advisor names the part that failed and how to fix it.

Redrawn 2026-10-10 After a plugin release, the cloud picks up the advisor's new version by itself where the platform allows it. Where it can't, you paste new setup text.

Journey 2 · every build

Deciding where a build runs

The advisor is about to launch a build

↓

Your launch word wins if it names a place"This one local", or "this one in the cloud".

↓

Otherwise the project's setting decidesSwitched on: the cloud is the default. Switched off: local, as today.

↓

Can this build run in the cloud?Not if it needs something only your machine has, such as a phone simulator or your signed-in browser. The advisor judges this from the order.

↓

Is the cloud ready right now?Reviewer pass live, setup done on this account, same plugin version as the advisor, calibration matches, platform up.

↓

Yes to both: it launches in the cloud
No to either: it launches on your machineNever held, never dropped.

↓

The launch report says which build went whereFor each local one: why, and what to fix. The advisor keeps saying it until it is fixed.

Journey 3 · every cloud build

A cloud build's life

The builder works on a cloud machineIt pushes its work often. Your machine can be asleep.

↓

It shows up in the advisor's wave picture like any laneCounted, watched, and marked as a cloud lane.

↓

A question for the advisor is a comment on the issueThe advisor answers the builder directly. While the advisor is away, the question waits on the issue.

↓

The independent reviewer reviews, through the passIf the pass has lapsed, the review counts as not run and the PR parks. Never a same-family stand-in.

↓

The builder opens the ready PRThe review record and receipts are on the PR. Nothing that matters is left only on the cloud machine.

↓

The advisor vets it, as for any build

↓

You give the merge word, as for any buildA cloud builder never merges.

If a cloud builder dies or stalls, the advisor recovers the lane at once from its pushed work, and the recovery is routed like a launch (journey 2).

Journey 4 · after each merge

Cleaning up a finished cloud builder

The advisor asks the builder to archive its own session

↓

You get one prompt and tap "Allow once"It works from your phone. The platform requires a person for this step.

↓

Tapped: the session is archived
Not tapped: the session stays listedNothing breaks.

↓

Everything else is already cleanThe PR branch is gone, the cloud machine is reclaimed, the lane's record is closed, and nothing was ever on your machine.

Journey 5 · each gardening pass

Keeping the reviewer pass alive

The gardening pass reads how long the pass has leftA pass lasts 10 days. Nothing warns between gardening passes.

↓

It will last to the next pass: nothing to do
It won't: you renew it now, by handA fresh pass, pasted into the cloud environment.

↓

If it lapses anyway, builds run on your machineThe launch report says so until the pass is renewed (journey 2).

Unchanged

What stays exactly as it is for a local build

  • The review rules, the advisor's vet and your merge word.
  • How orders are written and how a lane is recorded and counted.
  • A project with cloud builds switched off behaves as it does today.

Not in this piece

What waits or stays local

  • Hands-off upkeep of the reviewer pass and the calibration copy. That is the later piece.
  • The advisor, discovery and the detective. They stay on your machine.
  • Any check that needs a phone or your signed-in browser.
  • Cleanup with no tap. It stays the aim if the platform ever allows the approval in advance.
