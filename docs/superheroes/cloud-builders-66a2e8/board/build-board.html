1 · Once per project, per Claude account

Setting a project up for the cloud

The advisor, in chat, when you ask for cloud builds

Setting up cloud builds for Corner Shop. You do three things by hand, once, on claude.ai. It takes about ten minutes.

  1. Make a cloud environment for this project.
  2. Paste the setup text into it. I've written it below.
  3. Paste the reviewer pass into it. Run the pass command on your machine and it puts the pass on your clipboard.

Two things to know before you start.

The reviewer pass will sit in that environment's settings, and any session started in that environment can read it. It is a separate sign-in from your main one, it cannot renew itself, and it stops working after 10 days.

Cloud builders do not get your personal instructions or permission rules. They follow this project's rules and the plugin's rules, and nothing else.

Tell me when all three are done and I'll run a short check.

A block to copy and paste. It holds no secret. The pass never goes in here.

The check passed

The check passed.

The check is one short cloud session. A failed check always names the part that failed and the fix.

2 · A per-project setting

Switching cloud builds on and off

Switched on

Cloud builds are on for Corner Shop. From the next launch, every build that can run in the cloud will.

Say "this one local" at any launch to keep a build on your machine.

Switched off

Cloud builds are off for Corner Shop. Builds run on your machine, as before.

The cloud setup is kept, so switching back on needs no new setup.

Asked for before setup is done

Cloud builds can't be switched on yet. This project has no cloud setup on this Claude account. Say "set up cloud builds" and I'll walk you through it.

Every reason a build runs on your machine, as worded

  • You said "this one local".
  • It needs the phone simulator, which only your machine has. (Or whatever it needs.)
  • The reviewer pass has lapsed.
  • There is no reviewer pass in the cloud environment.
  • This project has no cloud setup on this Claude account.
  • The cloud's plugin is 0.41.0 and mine is 0.42.0.
  • The cloud's calibration doesn't match this machine's.
  • The cloud platform couldn't be reached.

Each reason the cloud wasn't ready comes with its fix. A build is never held and never dropped.

5 · Rare

When something goes wrong mid-build

The pass lapsed during a build · the builder, on its PR

Parked: the review did not run.

The reviewer pass lapsed during this build, so no independent review happened. The work is pushed and this PR is not ready. It needs a fresh pass, then a review.

The advisor, to you

#413 is parked. The reviewer pass lapsed mid-build, so its review didn't run. Renew the pass and I'll send it back for review.

Redrawn 2026-10-10 No session picks a same-family reviewer on its own. Your word, for that PR, can send it through with one, marked as not independent, or without the review. The same rule as for a build on your machine.

A cloud builder stopped · the advisor, to you

The cloud builder on #412 stopped at 14:02. I recovered the lane from its pushed work in a new cloud session. About 6 minutes of work since its last push is being redone.

Recovered at once, like any dead lane, and routed like a launch: in the cloud if the cloud is ready, otherwise on your machine.

These are the platform's words, not the plugin's, so they can't be changed. One prompt per finished builder, and it works from your phone.

If you don't answer

The session stays in your list, and nothing breaks. The PR branch is already gone, the cloud machine is reclaimed, the lane's record is closed, and nothing was ever on your machine.

The plugin doesn't nag about unanswered prompts.
